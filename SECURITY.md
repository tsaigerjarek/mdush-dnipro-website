# Безпека та захист даних

Цей файл описує мінімальні організаційні правила для репозиторію. Він не замінює юридичну консультацію, внутрішні політики або окремі погодження.

## Секрети

- Локальні секрети можуть зберігатися у виключеному з Git файлі `.env`.
- Секрети для тестового та production-середовища мають зберігатися у захищеному сховищі відповідної платформи.
- Секрети заборонено зберігати у GitHub-файлах, документації, коді, Issues та Pull Request.
- `.env.example` містить лише порожні поля без реальних значень.
- Ідентифікатори Google Workspace не публікувати як змінні клієнтської частини; використовувати їх лише у відповідному захищеному серверному або платформному контексті.
- Перед Pull Request перевіряти диф і нові файли на секрети.
- Якщо секрет випадково потрапив у гілку, не публікувати його далі: зупинити роботу, повідомити власника проєкту та замінити або відкликати секрет у відповідній системі.

## Персональні та медичні дані

- Не додавати до цього репозиторію окремі персональні або медичні дані дітей: списки, дати народження, адреси, телефони, медичні відомості, приватні ідентифікатори чи документи.
- Фото й відео дітей не додавати автоматично або без перевірки.
- Для можливої майбутньої публікації фото або відео потрібні підтверджене право використання, визначена законна підстава або належне погодження, редакційна перевірка та дозвіл відповідальної особи.
- Публікувати лише відібрані оптимізовані копії. Перед публікацією перевіряти метадані, геолокацію, приватну інформацію та безпечність контексту.
- Великі оригінали фото й відео зберігати в Google Drive або іншому окремо погодженому сховищі поза GitHub.
- На поточному етапі реальні фото й відео дітей не додавати. Майбутня публікація офіційних командних або матчевих матеріалів можлива лише після виконання всіх зазначених вимог.
- Якщо матеріал містить чутливі дані, не редагувати його для публікації навмання: повернути на перевірку відповідальній особі.

## Джерела істини та сховища

- GitHub є джерелом істини для програмного коду, структури сайту, конфігурації без секретів, погоджених текстів, оптимізованих публічних матеріалів, метаданих і журналу змін.
- Google Drive є основним сховищем великих оригіналів фото й відео, робочих матеріалів, внутрішніх та непублічних документів.
- На сайті та в GitHub можуть зберігатися лише погоджені оптимізовані публічні копії.

## Доступи та GitHub

- Використовувати найменші необхідні права доступу.
- Не передавати доступи через коміти, Issues, Pull Request або публічні посилання.
- Не зливати зміни в `main` і не публікувати сайт без явного погодження.
- Не створювати Actions, secrets репозиторію або інтеграції без окремого доручення.

## Реакція на інцидент

У разі підозри на витік секрету чи даних:

1. Не копіювати й не поширювати знайдене значення.
2. Зафіксувати лише шлях до файла та тип проблеми без чутливого вмісту.
3. Повідомити власника проєкту.
4. Відкликати або замінити секрет у системі-власнику.
5. Перевірити історію та доступи після погодження плану виправлення.

## Перевірка перед PR

Перевірити:

- що зміни виконані не в `main`;
- що немає секретів, персональних або медичних даних;
- що документи та медіа мають зрозумілий статус;
- що не додано великих оригіналів фото чи відео;
- що сайт і розгортання не запускалися без окремого доручення.
