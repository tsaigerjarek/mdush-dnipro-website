# Безпека та захист даних

Цей файл описує мінімальні організаційні правила для репозиторію. Він не замінює юридичну консультацію, внутрішні політики або окремі погодження.

## Секрети

- Не зберігати в GitHub паролі, токени, API-ключі, приватні ключі, cookies, службові JSON-файли чи значення доступу.
- Локальні секрети зберігати тільки у файлі `.env`, який не додається до репозиторію.
- `.env.example` містить лише порожні поля або очевидні безпечні приклади без реальних значень.
- Перед Pull Request перевіряти диф і нові файли на секрети.
- Якщо секрет випадково потрапив у гілку, не публікувати його далі: зупинити роботу, повідомити власника проєкту та замінити або відкликати секрет у відповідній системі.

## Персональні та медичні дані

- Не додавати до цього репозиторію персональні або медичні дані дітей.
- Не зберігати списки дітей, дати народження, адреси, телефони, медичні відомості, документи, приватні ідентифікатори або інші дані, що дають змогу ідентифікувати дитину.
- Не додавати фотографії чи відео, що ідентифікують дітей, без окремої документованої правової та редакційної перевірки; на цьому етапі такі матеріали не додаються.
- Якщо матеріал містить чутливі дані, не редагувати його для публікації навмання: повернути на перевірку відповідальній особі.

## Доступи та GitHub

- Використовувати найменші необхідні права доступу.
- Не передавати доступи через коміти, Issues, Pull Request або публічні посилання.
- Не зливати зміни в `main` і не публікувати сайт без явного погодження.
- Не створювати Actions, secrets репозиторію або інтеграції без окремого доручення.

## Реакція на інцидент

У разі підозри на витік секрету чи даних:

1. Не копіювати й не поширювати знайдене значення.
2. Зафіксувати лише шлях до файла та тип проблеми без чутливого вмісту.
3. Повідомити власника проєкту.
4. Відкликати або замінити секрет у системі-власнику.
5. Перевірити історію та доступи після погодження плану виправлення.

## Перевірка перед PR

Перевірити:

- що зміни виконані не в `main`;
- що немає секретів, персональних або медичних даних;
- що документи та медіа мають зрозумілий статус;
- що не додано великих оригіналів фото чи відео;
- що сайт і розгортання не запускалися без окремого доручення.
