# Аудит поточного сайту МДЮСШ Дніпро

Дата: 5 серпня 2026 року

## Технічна основа

- Репозиторій: `tsaigerjarek/mdush-dnipro-website`.
- Основна гілка: `main`.
- Фреймворк: Astro.
- Мова: TypeScript та Astro-компоненти.
- Публікація: GitHub Pages.
- Базовий шлях: `/mdush-dnipro-website/`.
- Контент новин: Astro Content Collections.
- Перевірки: `astro check`, production build, route tests, quality tests і deployment tests.

## Сильні сторони

1. Уже існує робочий офіційний MVP, тому міграція на інший фреймворк не потрібна.
2. Є централізований `BaseLayout`, спільні `SiteHeader` і `SiteFooter`.
3. Реалізовано canonical URL, Open Graph, skip-link і базову SEO-структуру.
4. У репозиторії є документація щодо юридичних фактів, Google Workspace, контенту, безпеки та розгортання.
5. GitHub Pages workflow і тести розгортання вже є частиною проєкту.

## Виявлені структурні проблеми

### P1 — інформаційна архітектура

- Головна навігація покривала лише шість розділів і не виводила тренерський склад, матчі та події, новини як окремий розділ і документи.
- Назва «Відділення» у навігації менш зрозуміла для батьків, ніж «Спортивні напрями».
- «Прозорість» одночасно виконувала роль принципів публікації та каталогу документів. Ці функції потрібно розділити.
- Немає окремого центру тренерського складу.
- Немає єдиного розділу матчів, результатів і подій усіх спортивних напрямів.

### P2 — головна сторінка

Поточна головна працює як офіційна візитка, але потребує поступового додавання таких модулів:

- офіційна ідентифікація закладу;
- шлях розвитку вихованця;
- найближчі матчі та події;
- останні результати;
- попередній перегляд тренерського складу;
- медіавітрина;
- локації;
- документи та прозорість;
- окремий маршрут для батьків.

### P2 — компоненти

У репозиторії фактично є лише два глобальні компоненти. Повторювані картки й секції потрібно поступово винести в окремі компоненти:

- `SectionHeader`;
- `SportCard`;
- `CoachCard`;
- `MatchCard`;
- `EventCard`;
- `ResultCard`;
- `NewsCard`;
- `DocumentCard`;
- `LocationCard`;
- `AdmissionSteps`.

### P2 — контентні дані

Окремі масиви та повторювані дані потрібно централізувати для:

- навігації;
- спортивних напрямів;
- тренерів;
- матчів і подій;
- документів;
- локацій;
- офіційних каналів.

## Принципи наступної версії

- Зберегти Astro й статичну генерацію.
- Не додавати сервер, базу даних або особисті кабінети до офіційного MVP.
- Не публікувати персональні дані дітей.
- Не вигадувати юридичні дані або документи.
- Публікувати матчі, події та тренерські відомості лише після перевірки.
- Зберігати рівноправне представлення футболу, настільного тенісу та черлідингу.
- Використовувати компактні компоненти й мінімум клієнтського JavaScript.

## Перший виконаний етап

У гілці `feature/site-structure-v2`:

- розширено основну навігацію;
- «Відділення» перейменовано на «Спортивні напрями»;
- додано сторінку тренерського складу;
- додано сторінку матчів та подій;
- додано окремий центр документів.

## Наступні технічні кроки

1. Перевірити нову навігацію на ширинах 320, 768, 1024 і 1440 px.
2. Винести масив навігації в окремий файл даних.
3. Оновити sitemap і route tests для нових сторінок.
4. Додати нові розділи на головну сторінку.
5. Створити повторно використовувані картки.
6. Перевірити Lighthouse, контрастність і вагу зображень.
7. Після CI-перевірок сформувати окремий PR для головної сторінки.
