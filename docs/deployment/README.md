# Розгортання

## Обрана платформа

Перша версія сайту готується до розгортання в GitHub Pages із репозиторію `tsaigerjarek/mdush-dnipro-website`.

- production-адреса до підключення власного домену: `https://tsaigerjarek.github.io/mdush-dnipro-website/`;
- джерело публікації: GitHub Actions;
- гілка публікації: `main`;
- каталог готового статичного сайту: `dist`;
- сайт не потребує серверного виконання, бази даних або секретів.

## Коли запускається workflow

Workflow `.github/workflows/deploy-pages.yml` запускається:

- після зміни в `main`;
- вручну через `workflow_dispatch`.

Draft Pull Request не запускає розгортання. Перше розгортання можливе лише після окремого погодження, злиття PR №9 у `main` і вибору `GitHub Actions` у `Settings → Pages → Build and deployment → Source`.

## Перевірки перед артефактом

Workflow виконує `npm test`, що включає:

- Astro і TypeScript;
- статичну збірку;
- перевірку маршрутів;
- метадані, заголовки, зображення, внутрішні посилання, `robots` і контраст;
- production base path, canonical URL та `sitemap.xml`.

Артефакт передається до GitHub Pages лише після успішного завершення перевірок.

## Власний домен

Власний домен, DNS, файл `CNAME` і примусове HTTPS не входять до PR №9. Їх потрібно налаштовувати окремо після перевірки першого розгортання за тимчасовою адресою GitHub Pages.

## Перевірка після першого розгортання

1. Перевірити успішний workflow у вкладці `Actions`.
2. Відкрити production-адресу й перевірити всі 11 HTML-сторінок.
3. Перевірити мобільний вигляд і клавіатурну навігацію.
4. Перевірити `robots.txt` і `sitemap.xml`.
5. Перевірити canonical та Open Graph URL.
6. Провести Lighthouse для ключових сторінок.
7. Лише після цього окремо вирішувати питання домену, DNS і HTTPS.
