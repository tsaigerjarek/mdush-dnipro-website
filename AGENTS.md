# Правила роботи Codex

## Мова та стиль

- Спілкування, документація, назви організаційних матеріалів і повідомлення комітів — українською мовою.
- Писати стисло, зрозуміло та без припущень.
- Публічні тексти готувати лише на основі підтверджених джерел.

## Перевірка перед змінами

- Перед будь-якими змінами перевіряти чинні файли, структуру репозиторію та всі актуальні інструкції.
- Не видаляти наявні файли без окремого явного доручення.
- Не вважати створення структури доказом готовності сайту, авторизації, інтеграцій чи розгортання.

## Гілки та погодження

- Усі зміни виконувати в окремій гілці; у `main` безпосередньо не працювати.
- Для змін створювати Pull Request, за замовчуванням Draft Pull Request.
- Злиття в `main`, публікація сайту та розгортання — лише після явного погодження власника проєкту.
- Не створювати GitHub Actions, автоматичне розгортання або інші автоматизації без окремого доручення.

## Достовірність контенту

- Заборонено вигадувати юридичні факти, контакти, тренерський склад, результати матчів, документи, регалії чи статистику.
- Непідтверджені дані позначати як `TODO` із коротким поясненням, що саме потрібно перевірити.
- Не підміняти офіційні джерела припущеннями, макетами або текстом, що виглядає як факт.

## Дані та медіа

- Не зберігати секрети, паролі, токени, API-ключі, персональні або медичні дані дітей.
- Не додавати до репозиторію великі оригінали фото й відео; використовувати лише погоджені оптимізовані копії, коли це буде окремо дозволено.
- Не додавати приватні документи або матеріали з невизначеними правами використання.

## Перевірка перед Pull Request

- Перевірити структуру файлів і те, що зміни залишилися в потрібній гілці.
- Перевірити відсутність секретів, персональних і медичних даних.
- Переконатися, що `main` не змінювався і не було запуску публікації чи розгортання.
- У PR описати, що змінено, що перевірено та що потребує погодження.
